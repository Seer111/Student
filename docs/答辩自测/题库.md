# 答辩自测题库

> 出题只从这里取；新题追加到本文件，不另起文档。
> 答法：**一句结论 → 为什么 → 什么情况下会坏**。共 5 题，中等难度。

---

**1. 复述评分和测评判分都会改知识点状态，为什么最后定成「只前进不回退」，而「该复习了」要单独用一个字段？**

阶段的语义是「能力长到哪一步」，应当单调；一次手滑或网络差导致的低分不该把「已掌握」打回「学习中」，否则颜色、统计和复习推荐都会来回抖。
「该复习了」是会反复发生的事，用另一个布尔字段表达，两者解耦，才能出现「已掌握 + 待复习」这个组合。

**2. 同一对知识点，如果既被手动建立了引用，正文里又提到了对方，图谱为什么只画一条边？优先保留哪一条？**

重复边会放大视觉权重、让节点度数虚高，图就不是「关系图」而变成「谁被提得多」的热力图。
所以按 `source→target` 去重，显式引用优先：用户确认过的语义比系统按标题猜出来的更可信。
边界是方向敏感——A 引用 B 和 B 提到 A 是两条不同的边，不会被合并。

**3. 向量库切块时块与块之间留了重叠，这个重叠是干什么的？不留会怎样？**

用来保住跨块的上下文：一句话被切在边界上时，重叠让相邻两块都能读到它，检索命中后拼出来的上下文才不会断。
不留重叠的代价是边界处的语义被切碎，问句刚好落在断点上就召不回来，表现为「答案明明在库里却搜不到」。

**4. 容器化部署后，前端页面能打开，后端却一直重启——你会先看哪三样东西？**

先看启动日志里的第一行报错（多数是缺环境变量，进程直接退出），再看健康检查（`/api/health` 是否真的返回 `db: up`），最后看依赖顺序（前端等后端 healthy 才起，否则就是 502）。
根因通常是「配置没进容器」而不是代码坏：compose 只读根目录的 `.env`，变量空串就会让服务自杀重启。

**5. 知识库问答检索结果为空时，接口应该返回什么？为什么不能直接让模型自由回答？**

应该返回「知识库里还没有相关内容」，并让 `sources` 为空——前端据此显式提示，而不是给一段看似合理的答案。
因为这个功能的价值是「可核对」：每个结论都要能点回知识点。放开自由发挥，模型会在没依据时编造，用户又分辨不出来，等于把可信度换成了流畅度。
