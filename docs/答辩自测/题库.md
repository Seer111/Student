# 答辩自测题库

> 出题只从这里取；新题追加到本文件，不另起文档。
> 答法：**一句结论 → 为什么 → 什么情况下会坏**。难度 L1 → L2 → L3 递增。

---

## L1 概念（凭用过的经验能答）

**1. 学习闭环是哪三步？每一步的产出是什么？**
学（录入知识点）→ 练（复述/测评）→ 评（AI 反馈 + 状态推进）。产出依次是：结构化内容、转录稿与分数、阶段与复习标记。

**2. 「已掌握」和「待复习」能同时出现吗？为什么必须是两个字段？**
能。阶段只前进（能力成长），复习标记可反复置位（该复习了）；合成一个字段就没法表达「已经掌握但需要复习」。

**3. 图谱里的颜色和大小分别表示什么？为什么不能只用颜色？**
颜色 = 学习状态，大小 = 关联数量。只用颜色表达不了「谁关联多」，而且颜色一多就分不清，色弱用户也读不出来。

**4. 复述和测评分别练什么？**
复述练「讲清楚」（表达与理解）；测评练「答得对」（掌握程度，错题进复习列表）。

**5. 桌面版和网页版共用构建产物，差别在哪一层？**
加载方式：网页走 `http://`（有域名、可刷新直达），桌面由 Electron 走 `file://`（本地文件）。因此路由、接口地址都要按协议分支。

## L2 机制（说清「怎么实现」）

**1. 复述为什么分成「转录」和「评分」两步？**
两个能力、两种故障：转录错是识别问题，评分错是判断问题。分开后转录可先给人核对，评分失败只重试评分，换模型互不影响。

**2. 知识点状态为什么会自动变？**
两条链路：复述评分（有分 → 学习中，≥85 → 已掌握）、测评判对（→ 学习中）。都走「只前进不回退」的判断，所以一次低分不会把已掌握打回去。

**3. 向量库为什么要把正文切块，而不是整篇存一个向量？**
一篇长文一个向量会把多个主题糅在一起，检索时只能整篇命中、拿不到具体段落。切块（带重叠）才能召回「最相关的几段」，也才能把依据精确定位到某段。

**4. 图谱的「引用」和「提及」分别从哪来？同一条关系为什么只画一次？**
引用来自用户手动的 `references`；提及来自正文里出现另一个知识点的完整标题。同一条 `source→target` 只保留一条，且显式优先——重复边会放大视觉权重、让度数虚高，而「用户确认过」比「系统猜的」可信。

## L3 边界（说清「什么时候会坏」）

**1. 桌面端为什么会白屏？**
`file://` 下地址里的路径是磁盘路径（`/E:/…/index.html`），网页那套路由一条都匹配不上，内容区渲染为空；标题和菜单正常是因为外壳照常加载。
修法：检测到 `file://` 就改用哈希路由。

**2. 容器里上传 1 MB 以上的录音报 413，本地却不复现？**
nginx 默认只允许 1 MB，而本地开发走 Vite 代理、不经过 nginx。
改法：放宽 nginx 的上传体积，同时确认后端自身的上传上限也够——两处都要改。

**3. 为什么状态「只前进不回退」？回退需求放哪？**
阶段是单调信号：一次手滑或网络差导致的低分，不该把「已掌握」打回「学习中」，否则页面颜色、统计和复习推荐都会抖。
回退需求用另一个字段表达（复习标记置位），两者解耦。
